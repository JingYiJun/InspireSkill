# 为兼容性而回滚的候选改进

这里记录**因为会改变 CLI 既有行为而被回滚、但本身可能更好**的写法。回滚的理由从来
不是「新写法不好」，而是「CLI 用户升级时不该察觉到变化」——判据是 `origin/main` 的
可观察行为即规格。等有意愿承担一次行为变更时，再逐条评估。

每条都应写清：改动是什么、为什么可能更好、回滚它付出了什么、真要采纳时需要配套做什么
（发版说明、迁移期、还是加开关）。

## 来自 codex/python-sdk 的复核（2026-09）

本轮复核找出七处 CLI 行为变更。其中五处是重构副作用，已按旧行为修复。另外两处经
评估确认是有价值的改进，**已决定直接采纳**，因此不再列为候选，改为按有意的行为变更
处理（见 CHANGELOG 的破坏性变更条目）：

- 工作负载状态值归一化（`hpc`/`ray` 的 `list`、`status`）
- 模型目录翻页（`serving create --model`）

采纳它们意味着 `--json` 的 `status` 取值与 `serving create` 的请求行为发生变化，
需要发版说明点名，详见 CHANGELOG。

## 当前无待决候选
